# 主题资产：谁是正本，改哪里

**一句话**：9 件自建**瓦作**是本库的正本，改这里。**2026-11-23 起上游主题一件不留**——配色起手式改由 `references/palette-atlas.md` 承接。

> **称呼**：本库把 9 个主题叫「**瓦作**」（屋面工艺：瓦、脊、滴水），把 36 个版式叫「**梁架**」，
> 把用户投进来的原始素材叫「**落雪**」。雪落在瓦上、不落在梁架上——所以雪归这一层。
> 详见 `SKILL.md` §三层词汇。⛔ 只是称呼，目录名不改。

## 先看坑（这四条都是真踩过的）

1. **同一套皮肤存两份，两个会话各改一侧**——2026-11-20 之前，这些自建皮肤在 `html-ppt-skill/assets/themes/` 里也有一份。两边都被改过，谁也说不清哪份是现行的，最后靠逐字节核对才收口。**判据**：任何主题文件在全盘只能有一个实体，另一侧只能是软链或指针。
2. **留着上游主题当备选**——36 件里真正被页面加载的只有 3 件，其余 33 件要维护却没人用，还多背 33 份第三方代码。**判据**：本目录只许有 9 件 `.css` ＋ 一份 `README.md`；备选配色进 `references/palette-atlas.md`，不落成文件。
3. **改上游色板以为改了自己**——反向依赖只有一条，指针跟着变是特性不是 bug；但反过来，改本库这 9 件不会影响上游，别指望「改一处两边都好」。
4. **以为主题能改版式**——主题只覆盖 token 与少量构件（`.pill` / `.quiz-opt` / `.glass` 等）。字号档位、行盒补偿、栅格在 `base.css`，改主题改不动它们。

## 二、备选配色：不落成文件

2026-11-23 上游主题全数删除（36 → 28 → 0）。六组经典骨架（素灰 / 终端墨 / 和纸 / 暖刊 / 铁线 / 霞粉）
收在 `references/palette-atlas.md`，只记 token 值与挑组四问，不生成 `.css`。

- 族页与示例的 `theme-link` 已从 `themes/upstream/*.css` 换成自建瓦作：layout 默认 `guanglan-rd`、
  暗底范例 `century-ave`。
- 要临时换气质：从图谱抄一组进 `assets/themes/<name>.css`，走完配色体检再算交付。
- ⛔ 不建指向 `html-ppt-skill` 的软链，也不复制其主题副本。

## 三、与上游的边界

主题层已无反向依赖：本目录 9 件全是自建实体，`ls -l` 首列再没有 `l`。
上游主题的任何一件都不再被链接、被内联、被引用；`build-deck.py` 只认本目录的 9 件。

## 四、为什么这么分

- **备选配色是判据不是资产**：写进图谱就够，落成文件只多一份要维护、要查重、要算许可的东西。
- **自建 9 件是活的**：版式 / 字号 / 材质仍在迭代，需要唯一正本。
- **主题的覆盖面有限**：只覆盖 token 与少量构件，版式骨架在 `base.css`。想让主题改版式，是找错了层。
