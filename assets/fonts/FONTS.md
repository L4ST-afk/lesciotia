# 字体清单与自备说明

## 两条路，任选一条

**A · 装到系统（推荐，最省事）**
下载 ttf/otf 双击安装到系统。主题 CSS 的 `@font-face` 写了 `local()` 优先匹配，
浏览器会**直接用你系统里的字体**，不加载随包子集。装完跑一次检测确认：

```bash
python3 scripts/check-installed-fonts.py        # 命令行
python3 scripts/check-installed-fonts.py --html # 出检测页，浏览器里实测
```

**B · 放进仓库（适合要分发给别人）**
把文件放到下表路径，随包走。适合你要把 deck 发给别人、对方没装字体的情况。

两条路可以混用：装了的走系统，没装的走子集，互不影响。

## 不随包分发第三方字体

本 skill **不随包分发第三方字体文件**。9 个主题里 7 款标题/正文字体需要你自行下载，
放进对应目录后即可生效。缺字体不会报错，会**静默回落到系统字体**（每款字体的回退链
都写在主题 CSS 的 `--ff-title` / `--ff-body` 里），页面照常渲染，只是没有那款字的笔意。

⛔ 唯一例外：**万航渡喜脉体**是本库自己派生的（裁 GB2312 一级字子集 + 沿轮廓机械加粗
+100/2048 em），按 SIL OFL 1.1 允许再分发，随包提供。

## 为什么这么做

字体是**文件**，不是风格。风格（龙华寺、万航渡、画稿纸、梧桐绿）谁都可以用，
但把 woff2 放进公开仓库属于**再分发**，需要授权允许。本库 7 款字体里只有 3 款带
OFL 原文，2 款只有「免费商用」的使用授权（不等于允许再分发），2 款连随包许可文本
都没有。所以统一改成「自备」：不打包就不构成再分发，授权问题消失。

## 龙华寺的标题：爨八体 + 标点回落霞鹜文楷

`longhua-si` 的标题链是：

```
'CuanBaTi','LXGWWenKai','霞鹜文楷','Source Han Serif SC',…,serif
```

### 为什么必须两段

**爨八体只有汉字。** 实测它的 `cmap` 里：

| 类别 | 数量 | 在爨八体里 |
|---|---|---|
| 汉字（GB2312 全集） | 6763 | ✅ 全有 |
| ASCII 可打印字符 | 95 | ❌ 一个都没有 |
| 常用全角标点 | 27 | ❌ 一个都没有 |

所以标题里出现「·」「，」「2026」「ABC」时，浏览器会**逐字**回落到霞鹜文楷。
这是设计上的混排，不是缺字——霞鹜文楷同为楷体，笔意接近，混排不刺眼。

⛔ **不许把霞鹜文楷从链里去掉**：去掉后标点会一路掉到系统默认宋体，楷书笔意断裂。
⛔ **不许给爨八体加 `unicode-range`**：它本来就没有标点码位，加了也没用，反而增加误判。

### 为什么不再有 han-only 策略

旧版 `longhua-si` 用 `@font-policy han-only` 强制「标题只承载汉字，标点回落系统宋体」，
因为当时的标题字体（法华文楷完整版）含标点，会把标点截走。

2026-11-21 标题换成爨八体后，**这个策略自然失效**——爨八体根本没有标点码位，
不存在「截走标点」的可能。所以 `@font-policy han-only` 已移除，`unicode-range` 也不再需要。

### 伪粗问题

标题规则写 `font-weight:700`，但爨八体只有一个字重（usWeightClass 400）。
`@font-face` 里**只声明 `font-weight:400` 单值**，让 700 请求回落到 400 原字形。

⚠️ 若声明成 `font-weight:400 700` 区间，浏览器会拿 400 的字形**合成伪粗**——
书法字体一合成，飞白和三角点就糊成一团。这是实测过的坑。

### 法华文楷：现在是提示项

法华文楷（© 谢宏雲 / 文徵字库）**不随包、不声明 `@font-face`**。
原因：zfont.cn（font_777）把许可标为**嵌入禁止、衍生禁止**，商标也禁止；
许可协议栏为「无标准协议（作者文字声明）」，原文在小红书笔记（需 App 扫码，抓不到）。
本库的用法正是把 woff2 当网页字体嵌入——落在被禁止的那一项里。
字体 `nameID 13/14` 空。页面另有「系统检测该字体疑似由 AI 生成」警告。

想用的用户：自己装「法华文楷标准版」，把 `--ff-title` 首位改成 `'法华文楷标准版'` 即可
（系统字体，浏览器直接命中，不需要 `@font-face`）。
实测可命中的名字：中文族名「法华文楷标准版」、PostScript 名「FahwaWenkai-Standard」。

## 南西油墨宋的授权：OFL 已登记，但缺随包原文

作者松陵南西（nanxiiii.taobao.com）。字体 `name` 表里**没有 License 字段**（nameID 13 缺失），
仓库目录里也没有 OFL.txt。作者公众号原文只说「使用 ps 调的油墨做旧效果，然后导出重新封装成字体」。

**但 zfont.cn 的登记是 SIL OFL**（`zfont.cn/cn/font_779.html`，2026-11-21 实测）：
许可协议栏标 `SIL开源字体许可 (OFL)`，许可范围七项**全为允许**——商标、嵌入、文稿、互联网、
视频、印刷、**衍生**。推荐指数 50，S 级，页面无 AI 生成警告。

所以「能不能内化」这一层是通的。缺的是**随包许可原文**：作者公众号正文只写「免费商用」，
没写 OFL 条款，字体文件里也没有。**结论仍是「自备」，但理由不是「授权不明」，
而是「授权依据没落成随包文件」。** 对外分发前补一份 zfont 页面或作者声明的存档即可。

⚠️ 上一轮曾据「公众号没提思源宋体」推断它不是 OFL 衍生、不能内化。这个推理有漏洞：
**作者没提 OFL 不等于没有 OFL。** 已修正。

关于「是不是基于思源宋体」：**没有证据支持，实测反而否定。** 见下节。

## 怎么判断一款字体是不是「基于思源宋体」

这是 2026-11-21 实测南西油墨宋时总结的方法。结论：**南西不是思源宋体的衍生**。

### 先看元数据（快，但会骗人）

| 检查项 | 思源宋体 SC | 南西油墨宋 |
|---|---|---|
| `name` 表 License 字段 | SIL OFL 1.1 原文 | **缺失** |
| Copyright | Adobe Systems Incorporated | nanxiiii.taobao.com |
| 轮廓格式 | CFF / OTF | TrueType `glyf` |
| upem | 1000 | **256** |
| 字形数 | 65535 | 3872 |

upem 从 1000 掉到 256、CFF 变 `glyf`、点数从 89 涨到 2118，说明它**位图化后重新矢量化**过
（对应作者说的「PS 调油墨做旧后导出重新封装」）。所以**不能用点数或 upem 判断同源**。

### 再做像素骨架比对（可信）

把两款字体渲染成同尺寸二值图，对齐包围盒后算 IoU。**关键是要有对照组**，
否则单看一个数字没有意义。

139 个常用汉字，`100px` 渲染，`160×160` 画布：

| 对比 | 平均 IoU | 平均投影轮廓相关 |
|---|---|---|
| 南西 vs 思源宋 | 0.4321 | 0.5741 |
| 南西 vs 宋体 SC Regular | 0.4354 | 0.6005 |
| 思源宋 vs 宋体 SC Regular | **0.5321** | **0.7079** |

**读法**：南西对思源宋（0.4321）和对宋体（0.4354）几乎等距，不偏向任何一方。
而思源宋和宋体这两款**确实同风格**的字体之间是 0.5321 / 0.7079，明显更高。
南西跟谁都不像，说明它是独立字形。

早期还跑过思源黑对照：南西 vs 思源宋 0.4321，南西 vs 思源黑 0.4316，
两款等距到小数点后三位 —— 同样不支持「以思源宋为基底」。

⚠️ 两个坑：
1. **字重必须匹配**。第一次拿 `Songti.ttc` 的第 0 个 face 是 **Black**，重体之间天然重叠多，
   得出「南西更像宋体」的假结论。要按 face 名挑 Regular。
2. **油墨做旧会压低所有 IoU**。南西墨量比思源宋多 22%（371117 vs 304304 px），
   所以它的绝对值天然偏低，只能看**相对关系**。

### 油墨质感怎么验收：14px 墨量是尺，⛔ 别在放大档标定

想复刻南西那种「油墨做旧」质感时，判据是**正文尺寸（14px）的墨量**，不是放大档看着像。
2026-11-22 实测：从思源宋生成四档墨点字体，96px 下梯度漂亮、heavy 档有油墨感；
14px 同句同画布二值化数墨点却全部塌回基线——

| 字体 | 14px 墨点像素 | 相对思源宋 |
|---|---|---|
| 思源宋（基底） | 878 | 1.00 |
| 南西油墨宋（目标） | 1150 | **1.31** |
| 生成四档 hairline/light/medium/heavy | 890–901 | 1.01–1.03 |

判据（详见禅院塔 §2.361）：①先定最终呈现尺寸再定量具，放大档只看机制、⛔ 不当达标场；
②在最终尺寸量，且**同时量基底与目标读相对倍数**（只有绝对数判不出够不够）；
③至少量最小＋最大两点，两点相反取小尺寸。

⇒ **所以别自己从思源造油墨字**：南西油墨宋已随包（`assets/fonts/nanxi/`，
SIL OFL 七项全允许含衍生），改主题 `--ff-title` 直接用即可，零标定、零授权风险。

### 授权怎么查：zfont.cn 的「许可范围」七项标签

`name` 表只能告诉你**作者自己写没写**许可，写没写不等于有没有。zfont.cn 的字体页有一栏
「免费商用—许可范围」，七个标签各自带 `class="can"` 或 `class="not"`，是**允许/禁止**的明确判定：

| 标签 | 含义 | 对本库的意义 |
|---|---|---|
| 商标 | 用于商标注册 | 一般用不到 |
| **嵌入** | 嵌入软件/网页/文档 | ⚠️ **本库的核心用法**（woff2 当网页字体） |
| 文稿 | 文档、PPT | 允许 |
| 互联网 | 网页、自媒体 | 允许 |
| 视频 | 影视、广告 | 允许 |
| 印刷 | 出版物 | 允许 |
| **衍生** | 修改、做派生字体 | ⚠️ **裁子集算不算，取决于此** |

读法：`class="can"` = 允许，`class="not"` = 禁止。页面文本里看不出区别（都是同一个词），
必须读 DOM 的 class 或样式。

2026-11-21 实测三款：

| 字体 | 许可协议栏 | 商标 | 嵌入 | 文稿 | 互联网 | 视频 | 印刷 | 衍生 |
|---|---|---|---|---|---|---|---|---|
| 南西油墨宋 | SIL OFL | can | can | can | can | can | can | **can** |
| 法华文楷 | 无标准协议（作者文字声明） | not | **not** | can | can | can | can | **not** |
| 摇醒青年黑 | 作者文字声明 | can | **not** | can | can | can | can | **not** |

⚠️ **zfont 的判定不等于作者原文。** 南西那款 zfont 标 OFL，但作者公众号通篇没提 OFL；
法华文楷标「无标准协议」，说明作者只发了文字声明。**zfont 是二手登记，作者原文才是一手证据。**
两者冲突时以作者原文为准，并把冲突记下来。

### 摇醒青年黑：为什么改成「不随包，只走 local()」

2026-11-21 处置。zfont.cn 把它的许可范围标为**嵌入禁止、衍生禁止**，而本库原先正是把
`YaoxingYouthHei-Subset.woff2` 当网页字体嵌入 `friendship-bldg.css`。作者声明 PDF 的
12 类免费商用场景里**没有一类是「网页字体嵌入」**，也没提再分发；声明给的是「不可转让」的
非专有许可，随仓库分发字体文件在字面上与「不可转让」冲突。

**处置（两道动作，缺一不可）**：

1. `@font-face` 只保留 `local()`，删掉 `url()`。
2. **子集 woff2 从仓库删除**。只删 `url()` 而留着文件，等于再分发风险还在——这次要消除的
   正是「随仓库分发字体文件」这个动作本身。`assets/fonts/yaoxing/` 现在只剩作者的
   免费商用声明 PDF。

效果是——

- 用户**自己装了**摇醒青年黑 → 标题用他自己的摇醒。这是用户自己的使用行为，不涉及本库再分发。
- 用户**没装** → 沿 `--font-display` 回退链落到**宋骨黑体**（内化 OFL 1.1），同为黑体，
  版式、色板、字距全不受影响，只是少了摇醒的撇点宋意。

**本机安装（开发机）**：原版 ttf 在坚果云 `字体/摇醒青年黑/摇醒青年黑1.0-Regular.ttf`
（5,640,276 B，7026 字形，`usWeightClass 400`）。已复制到 `~/Library/Fonts/`，
macOS 自动扫描该目录，`check-installed-fonts.py` 报「已装：摇醒青年黑1.0」。

#### ⛔ `local()` 必须写**全名**，不是族名也不是 PostScript 名

这是 2026-11-21 踩的坑，花了半小时才定位。该字体三个名字分别是：

| nameID | 值 | `local()` 能否命中 |
|---|---|---|
| 1（族名） | `摇醒青年黑1.0` | ❌ 失败 |
| 4（全名） | `摇醒青年黑1.0 Regular` | ✅ **唯一能命中的** |
| 6（PostScript 名） | `1.0-Regular` | ❌ 失败 |

**CoreText 层面三个名字都能解析到同一个字体**（`CTFontCreateWithName` 全部返回
family=`摇醒青年黑1.0` / ps=`1.0-Regular`），所以用 Python 或系统字体册查是查不出问题的
——必须在浏览器里实测 `new FontFace(name, 'local("...")').load()`。

正确写法（全名放第一位，其余留作兼容）：

```css
src:local('摇醒青年黑1.0 Regular'),local('摇醒青年黑1.0'),local('1.0-Regular');
```

验证方法：`document.fonts` 里该族的 `status` 从 `error` 变 `loaded`，
且回退字体（宋骨黑体）从 `loaded` 变 `unloaded`——后者才证明标题真的换了字体，
因为浏览器只在真正用到网页字体时才加载它。

⚠️ 顺带发现：这个浏览器环境对 CJK 族名的 `local()` 解析普遍不稳
（`PingFang SC`、`Songti SC`、`宋体`、`黑体` 全部失败，`STSong`、`SimSun`、
`SGH-Medium` 成功）。所以**任何走 `local()` 的 CJK 字体都要实测，别假设族名能用**。

⚠️ 回退链顺序不能反：`'SongguHei','宋骨黑体'` 必须排在 `'PingFang SC'` 之前，
否则没装摇醒的用户会掉到系统黑体，丢掉本主题「标题偏宋意」的设计意图。闸门 F4 会盯这个
（`--font-display` 引用了内化字体就必须有对应 `@font-face`）。

⚠️ 预览页 `examples/previews/friendship-bldg-theme-preview.html` 顶部有一条静态提示条，
告诉用户「未装则回落宋骨黑体，想要原设计可自行下载安装」。**不用 JS 探测**：模板是纯静态
单文件，加脚本会破坏「自包含、可直接双击打开」的承诺。

### 爱点风雅黑：同一个坑踩了第二次

2026-11-21 处置。zfont.cn（`font_657`）把许可范围标为**嵌入禁止、衍生禁止**，商标也禁止，
只允许文稿 / 互联网 / 视频 / 印刷——与摇醒青年黑完全一样的三项 `not`。而 `panyu-rd.css`
原先正是把 `AidianFengYaHei-Subset.woff2` 当网页字体嵌入。

作者官网《使用须知》全文只有一句「个人及企业可永久免费使用」，没提嵌入、没提再分发，
也没有任何标准协议（zfont 记作「无标准协议（作者文字声明）」）。字体 `name` 表
`nameID 13/14` 无许可声明，`nameID 0` 写「Typeface © (ideavi.cn). 2024. All Rights Reserved」
——「保留所有权利」与「永久免费使用」并排，能确定的只有「用」，不能确定「嵌」和「再分发」。

**处置**（同摇醒，两道动作）：

1. `@font-face` 只保留 `local()`，删掉 `url()`。
2. **子集 woff2 从仓库删除**（913 KB），`assets/fonts/aidian/` 只剩《使用须知》。

- 装了爱点风雅黑 → 标题用他自己的，不涉及本库再分发。
- 没装 → 沿 `--font-display` 回落**宋骨黑体**（SIL OFL 1.1，随包，`assets/fonts/songgu/`），
  同为黑体，版式色板不受影响。`@font-face` 写在本主题 CSS 内，与另外三个主题共用同一子集。
- 预览页顶部有静态提示条（赤陶配色）。

⚠️ **`local()` 的可用名字与摇醒相反**：爱点风雅黑用英文族名 `Aidian FengYaHei`
或 PostScript 名 `AidianFengYaHei-Regular` 都能命中，中文族名「爱点风雅黑」失败；
摇醒青年黑只有全名 `摇醒青年黑1.0 Regular` 能命中。**每款字体必须单独实测，
不能套用上一款的结论。**

### 授权结论

即使真的基于思源宋体（OFL 1.1），也**不等于可以随便再分发**：OFL 要求保留版权声明、
不得使用 Reserved Font Name。而南西**连 License 字段都没有**，作者也没声明 OFL。
「免费商用」是使用授权，不是再分发授权。所以这款仍按「自备」处理。

## 子集化（可选，但强烈建议）

上表的 ttf 原字动辄 7–20 MB，直接放进 deck 会让单文件产物大到没法发。本库所有字体
都是 **GB2312 一级字子集**（3755 汉字 + ASCII + 常用标点），裁完体积降到 1/4 左右。

```bash
pip install fonttools brotli
python3 -c "
from fontTools import subset
subset.main(['原字.ttf', '--text-file=gb2312.txt', '--flavor=woff2',
             '--output-file=目标.woff2', '--layout-features=*'])
"
```

`gb2312.txt` 需要包含你要用到的全部字符。本库的约定是 3755 一级汉字 + 62 拉丁数字
+ 空格。`longhua-si` 的爨八体子集是 **3757 个汉字**（GB2312 一级字全集 + 主题专用字），
不含标点数字——那些由回退链上的霞鹜文楷接住，见 `assets/themes/longhua-si.css`。

## 校验

放好字体后跑闸门确认：

```bash
python3 scripts/check-fonts.py          # 字体子集与声明一致性
python3 scripts/selftest.py             # 全量冒烟
```

`check-fonts.py` 的 F1 判据会检查：每个 `@font-face` 指向的文件**要么存在且含汉字，
要么在本清单里登记为「自备」**。两者都不是才报错。

## 缺字体会怎样

不会崩。每款字体的回退链都在主题 CSS 里写全了，例如：

- `wanhang-fy` 的 `--ff-title`：`'Wanhang Ximai' → '万航渡喜脉体' → 'Songti SC' → 'STSong' → 'SimSun' → 'Noto Serif SC' → 'Times New Roman' → serif`
- `longhua-si` 的 `--ff-title`：`'FahwaWenkai' → 'Source Han Serif SC' → '思源宋体' → … → '宋体' → serif`（无裸族名「法华文楷」，见上）

缺字体时直接落到链上第一个可用的系统字体。**版式、色板、间距全部不变**，只是标题
从手写体/楷书变成系统宋体或黑体。预览页和 deck 仍然能正常生成和交付。

## 拉丁内化（2026-11-23，v1.2.22 → v1.2.23）

`fonts/latin/` 收了四族 RIBBI 字面（每族 Regular + Bold）：Playfair Display、Inter、
Space Grotesk、JetBrains Mono。出生地是 Google Fonts 的静态实例，SIL OFL 1.1
（四族合并许可见 `latin/OFL.txt`）。

为什么收：这四族原先只写进 `fonts.css` 的声明栈，实体靠 `@import` 从
fonts.googleapis.com 拉——断网、内网、收件人机器没装，都会回落到 Times/Arial，
中英混排时西文部分的字重和字距就整段走形。现在 `@font-face` 指向本地 ttf，
`@import` 已删（Noto Sans SC / Noto Serif SC / IBM Plex Mono / Archivo Black 仍走 CDN，
它们只作骨架，不承担品牌字）。

收的边界：只收 RIBBI 四档。ExtraBold、SemiBold 这类在上游是独立族名（`Inter SemiBold`），
PowerPoint 的 bold 开关够不着，收了也用不上。

⚠ 一族一名：Space Grotesk 400 实例的 name 表内部族名被上游写成
「Space Grotesk Light」，CSS 里仍叫 `Space Grotesk`。PowerPoint 按 name 表匹配，
所以 C 出口的声明必须写内部名——`export-pptx.py` 的 `bundled_fonts()` 读 ttf 的
name 表取内部族名，再与 CSS 里的族名分开存，两边各说各话不会错。

为什么不在 pptx 里内嵌字体：`p:fntdata` 只吃 EOT 包裹的载荷，裸 ttf 会被静默忽略；
而且 macOS PowerPoint 与 Keynote 根本不读嵌入字体。替代做法是 `--bundle-fonts`：
把 ttf 拷到 `<out>-fonts/`，附 `安装字体.command` 与 README.txt，收件人双击一次即命中。
