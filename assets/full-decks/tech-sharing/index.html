幻灯片的问题不是不够好看，是没有规格。网页有规格，所以能测。

分享人：东十四

痛点

四个说不清的量

字号靠手感

同一个 32 号，在 4:3 和 16:9 里占的比例不同。

边距靠对齐线

拖动对齐，页与页之间差 3 到 8 像素，人眼看得出来。

色彩靠色卡

色卡不告诉你对比度够不够，投到墙上才知道糊。

版式靠截图

截图版式改不了字，改一个字要重做一张图。

第一件事

固定画布，再谈自适应

1920×1080 是设计画布，不是屏幕尺寸。缩放只做等比，元素位置永不变形。

/* 画布与缩放：所有 px 在投影、截图、导出里同一意思 */
.deck { width: 1920px; height: 1080px; transform: scale(var(--deck-scale)); }
.slide { padding: 72px 112px; font-size: 32px; }  /* 1pt = 2px */

逃逸口只有一个：body[data-fit="fluid"]，回到视口自适应，用于嵌进文档。

第三件事

色板三律

一页一个强调

第二强调只能同色相明度差，或与底色混合。

明度台阶四档

底、面、面二、边。少一档卡片就粘住。

墨字逐主题算

主色上放字要 ≥4.5:1，算不够就换墨色。

补充律：主色压底不足 3:1 时加 1px 描边，把边界立住，不动主色。

第四件事

能测的才叫规格

# 逐页量元素越界与压卡
python3 scripts/check-fit.py

# 量字数与套话
python3 scripts/check-prose.py spec.md

# 对比度、明度步长、色相暧昧带
python3 scripts/check-theme-colors.py assets/themes

# 文档说的数字与代码是否一致
python3 scripts/check_doc_claims.py

红即拒，不做「先交了再补」。

出口 · 三条路

同一个源，三种交付，代价不同

出口可改到多细适合
单文件 HTML元素级，可逐条线上、现场讲
PNG / PDF不可改，页级归档、发人
原生 PPTX形状与文本可编，逐组淡入交给同事续改
同一源

三出口都从同一份 token 与同一批 section 出，不维护三套稿。差异只在「改到多细」与「谁来接着改」。

取舍

明确不做的四件

对象级动效

B 出口按 data-build 逐条放；C 出口加 --animate，每页 ≤4 组、按回车逐组淡入。

非 sRGB 渐变

全部换算到可导出的近似，不承诺逐像素一致。

布尔运算求值

导出时求值，不在浏览器里跑几何引擎。

无尽主题

九件瓦作，每件有材质与出处，不批量生成。
