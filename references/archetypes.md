# 场景 archetype — 页序骨架

archetype 只回答一个问题：**这份 deck 第几页该说什么**。它不定视觉（那是风格系统的事），也不定页数（页数由内容长度决定，archetype 只给区间）。

选法：先按 `analysis-framework.md` 判内容类型，再按下表第一列的信号词命中；命中多个时取**交付目的**最近的那个（对外说服 → `pitch`/`launch`；对内交代 → `weekly`/`review`；教 → `course`/`tech-talk`/`explainer`；证 → `research`）。

## 1. `course` · 讲义 / 培训 / 工作坊

| 信号词 | 页数区间 | 默认风格 |
|---|---|---|
| 讲义、培训、workshop、教学、教案、内训、onboarding | 12-25 | `sketch-notes`（A）/ `academic-paper`（B） |

| # | 页型 | 这一页要干什么 |
|---|---|---|
| 1 | cover | 模块名 + 讲师 + 一句话收益 |
| 2 | objectives | 学习目标清单，**后续每页左侧常驻**（B 出口用固定栏；A 出口每页留一条目标条） |
| 3 | concept | 核心概念 A（定义 + 类比） |
| 4 | concept | 核心概念 B |
| 5 | example | 一个完整例子走通 A+B |
| 6 | practice | 练习/自测（选择题或填空） |
| 7 | answer | 答案 + 为什么（自测页必须有答案页，否则是废页） |
| 8 | wrap | 回顾目标达成情况 + 下一模块预告 |

**必备页型**：objectives（可常驻）、practice、answer。
**坑**：把目标页写成"讲义介绍"；自测页没有答案；例子页塞两个例子。

## 2. `pitch` · 融资 / 招商 / 合作提案

| 信号词 | 页数区间 | 默认风格 |
|---|---|---|
| 融资、pitch、seed、VC、投资人、招商、BP | 10-14（正文 10 页最稳） | `corporate`（A）/ `pitch-deck-vc`（B 有该主题） |

| # | 页型 | 这一页要干什么 |
|---|---|---|
| 1 | cover | 一句话定位（公司 + 做什么 + 给谁） |
| 2 | problem | 现状有多痛（一个数字或一个场景） |
| 3 | solution | 你怎么解（一图说清机制） |
| 4 | product | 产品实拍/界面（证明不是 PPT 公司） |
| 5 | traction | 增长曲线 + 3 个关键指标 |
| 6 | market | 市场大小与切入口（TAM/SAM/SOM 只讲一个） |
| 7 | competition | 2×2 或对比表，只跟 2-3 家比 |
| 8 | team | 为什么是你们（3 个人 + 各自一句硬履历） |
| 9 | ask | 要多少钱、怎么花、里程碑 |
| 10 | closing | 一句可记住的收束（不是"谢谢"） |

**必备页型**：traction、ask（$X.XM + 用途 + 里程碑）。
**坑**：traction 用"预计"；市场页讲三个口径；team 放六个人；ask 只说金额不说用途。

## 3. `tech-talk` · 技术分享 / 内训 / 架构评审

| 信号词 | 页数区间 | 默认风格 |
|---|---|---|
| 技术分享、架构、系统设计、内训、复盘技术方案、engineering | 12-22 | `blueprint` / `intuition-machine`（A）· `swiss-grid`/`engineering-whiteprint`（B） |

| # | 页型 | 这一页要干什么 |
|---|---|---|
| 1 | cover | 题目 + 一句话结论（不要只写标题） |
| 2 | why | 为什么现在讲这个（痛点或约束） |
| 3 | architecture | 一张总图（后续每页回到图上高亮一块） |
| 4-9 | walkthrough | 逐个模块走查：输入 → 处理 → 输出 + 关键取舍 |
| 10 | demo | 真实跑一遍（截图/终端/录屏帧） |
| 11 | gotchas | 3 个坑 + 怎么绕（这页最值钱） |
| 12 | takeaway | 一句结论 + 一条可执行建议 |

**必备页型**：architecture（可复用总图）、gotchas。
**坑**：总图只出现一次、后面全靠文字；demo 页贴代码全文；结论页重复封面。

## 4. `weekly` · 周报 / 项目进展 / 阶段汇报

| 信号词 | 页数区间 | 默认风格 |
|---|---|---|
| 周报、月报、进展、项目汇报、迭代、sprint | 8-12 | `notion`（A）/ `corporate-clean`（B） |

| # | 页型 | 这一页要干什么 |
|---|---|---|
| 1 | cover | 周期 + 一句话结论（先给结论，别让人翻到最后） |
| 2 | summary | 3 个数字讲清这一周 |
| 3 | progress | 做了什么（对齐目标的完成度，不是流水账） |
| 4 | risks | 卡在哪 + 谁在解 + 什么时候解 |
| 5 | next | 下周 3 件事 + 需要的支持 |
| 6 | appendix | 明细/数据来源（可折叠到最后一页） |

**必备页型**：risks（没有风险页的周报等于没写）、next。
**坑**：本周流水账占 5 页；风险写成"暂无风险"；下周计划没有责任人。

## 5. `launch` · 产品发布 / demo day

| 信号词 | 页数区间 | 默认风格 |
|---|---|---|
| 发布、launch、demo day、新品、开箱、上线 | 8-15 | `bold-editorial`（A）/ `magazine-bold`（B） |

| # | 页型 | 这一页要干什么 |
|---|---|---|
| 1 | cover | 产品名 + 一句宣言 |
| 2 | tension | 旧世界哪里不对（制造张力） |
| 3 | reveal | 揭晓（大图/大字/一段视频帧） |
| 4-6 | capability | 三个能力，一页一个，各自一个证据 |
| 7 | proof | 用户/数据/第三方背书 |
| 8 | cta | 怎么拿到 + 价格 + 下一步 |

**必备页型**：reveal、cta。
**坑**：能力页写功能列表而不是场景；证据页只有 logo 墙；CTA 只有"欢迎体验"。

## 6. `research` · 研究汇报 / 白皮书 / 论文答辩

| 信号词 | 页数区间 | 默认风格 |
|---|---|---|
| 研究、白皮书、论文、答辩、调研、实验、综述 | 12-20 | `scientific` / `intuition-machine`（A）· `academic-paper`（B） |

| # | 页型 | 这一页要干什么 |
|---|---|---|
| 1 | cover | 题目 + 一句结论 |
| 2 | question | 研究问题（可检验的那种） |
| 3 | method | 方法/数据/样本，一图说清流程 |
| 4-9 | finding | 每个发现一页：图表 + 一句话解释 + 一句局限 |
| 10 | limitations | 局限（自己先说，别等人问） |
| 11 | implication | 所以呢：对谁有用、下一步做什么 |

**必备页型**：question、limitations。
**坑**：发现页只有图没有解释；方法页贴公式；结论页夸大到超出数据。

## 7. `explainer` · 科普 / 长图 / 社媒图文

| 信号词 | 页数区间 | 默认风格 |
|---|---|---|
| 科普、解释、长图、小红书、图文、种草、一条讲清 | 6-12（单条 6-8 最稳） | `editorial-infographic`（A）/ `xiaohongshu-white`（B） |

| # | 页型 | 这一页要干什么 |
|---|---|---|
| 1 | cover | 一个钩子（反差/数字/问题），不是标题复述 |
| 2-7 | step | 认知台阶，一页一级，每级只用一种比方 |
| 8 | summary | 一图/一表总结（可截图单发） |

**必备页型**：summary（要能独立成图传播）。
**坑**：每页字数超 80 字（手机看不清）；专业术语不解释；总结页重复正文。

## 8. `review` · 复盘 / 评审 / 决策会

| 信号词 | 页数区间 | 默认风格 |
|---|---|---|
| 复盘、review、评审、决策、postmortem、结项 | 8-14 | `minimal` / `corporate`（A）· `minimal-white`/`corporate-clean`（B） |

| # | 页型 | 这一页要干什么 |
|---|---|---|
| 1 | cover | 复盘的什么 + 一句结论 |
| 2 | goal | 原定目标（当时怎么定的） |
| 3 | result | 实际结果（数字对数字） |
| 4 | gap | 差在哪（差距归因，不甩锅） |
| 5 | cause | 2-3 条根因（可验证的，不是"沟通不畅"） |
| 6 | decision | 要拍板的事（选项 + 推荐 + 代价） |
| 7 | action | 谁、做什么、什么时候、怎么验 |

**必备页型**：gap、decision、action。
**坑**：目标页用现在的口径改历史目标；根因写成形容词；决策页只给一个选项。

## archetype → 出口的注意点

| archetype | A 出口 | B 出口 | C 出口 |
|---|---|---|---|
| `course` | 目标条要每页出现（写进 prompt 的固定元素） | 用固定左栏 + `.notes` 放讲解 | 用母版放目标栏 |
| `pitch` | traction 页必须真数据，无数据用明显占位 | 用 `pitch-deck` 全 deck 模板打底 | 套品牌模板 |
| `tech-talk` | 架构图页要留出高亮位（每页同图不同高亮，需同一提示词底） | 可用 `tech-sharing` 模板 + 动效 | 原生形状画架构 |
| `weekly` | 数字页一页一个结论，别堆 | 周报模板 + 表格页 | 表格用原生 table |
| `launch` | 揭晓页可以最"费"（多试几版） | full-bleed 图片版式 | 需大图 + 动画时选 C |
| `research` | 图表页最好由数据出图后嵌入，别让模型画 | `academic-paper` 主题 + 图表版式 | 原生图表 |
| `explainer` | 每页独立可传播，封面即钩子 | 3:4 竖版：`.deck` 上设 `data-w="1080" data-h="1440"`（无现成 full-deck，拿 `assets/layouts/` 单页组） | 一般不用 C |
| `review` | 极简，靠排版不靠装饰 | `minimal-white` | 原生表格 + 批注 |
