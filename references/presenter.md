# 演讲者模式与讲稿

## 什么时候才需要讲稿

| 场合 | 要不要逐字稿 |
|---|---|
| 分享/内训/发布会/答辩（要开口讲） | 要，每页 150-300 字 |
| 阅读型 deck（发给别人自己看） | 不要写逐字稿；写一句"这页想让读者记住什么" |
| 交 PPT 给领导讲 | 要"提示卡"（每页 3-5 个要点），不写全文 |

判断信号：出现「演讲 / 分享 / 讲稿 / 逐字稿 / 提词器 / 上台 / 讲不流畅 / speaker notes / presenter view」任一，就按演讲型处理。

## 逐字稿三规则

1. **不是讲稿，是提示信号**：加粗核心词，过渡句独立成段。台上扫一眼就能接上，不需要逐字念。
2. **每页 150-300 字**：对应 2-3 分钟/页的节奏。少于 100 字说明内容没准备好；超过 400 字说明这页该拆。
3. **用口语，不用书面语**：「因此」→「所以」，「该方案」→「这个方案」，「进行」→「做」。

反例（不要写）："本页将阐述增长的三项来源。" —— 台上没人这么说话。
正例："这页就三件事：涨了多少、凭什么涨、多便宜。先看这个数：八倍。"

## B 出口的演讲者模式（本 skill 自带）

`assets/runtime.js` 已内建，无需额外装配：

| 键 | 作用 |
|---|---|
| `S` | 打开演讲者窗（弹出新窗口，四张磁性卡：CURRENT / NEXT / SCRIPT / TIMER） |
| `← →` | 观众窗与演讲者窗同步翻页 |
| `R` | 演讲者窗里重置计时 |
| `N` | 快速备注抽屉（当前页讲稿） |
| `O` | 总览宫格（选页跳转） |
| `#/N` | 深链到第 N 页（排练、截图、远程投屏都用它） |
| `Esc` | 关掉所有浮层 |

要点：

- **预览是像素级的**：演讲者窗的 CURRENT/NEXT 是同一份 deck 以 `?preview=N` 加载的 iframe，跟观众看到的 CSS/主题/字号完全一致——不是另做一套缩略图。
- **讲稿放 `<div class="notes">`**：`base.css` 默认 `display:none`，只在 `S`/`N` 时可见。**绝不能把提示文字写成正页上的小字**。
- **单文件也能用**：`build-deck.py` 打包后 `S` 照样可用；预览 iframe 加载的是同一个文件（因此主题已被收敛成单一主题，`T` 键不再换主题，这是预期行为）。
- **两窗同步靠 BroadcastChannel**，`file://` 下部分浏览器会限制，此时以"手动翻页 + 看 SCRIPT 卡"为准，不要卡在这里反复折腾。

## 现场级能力的边界（本库能到哪）

本库的演讲者模式由 `assets/runtime.js` 原生提供，**不需要外部引擎**：

| 能力 | 本库 | 说明 |
|---|---|---|
| 观众屏同步 | ✅ | `S` 键开新窗，`BroadcastChannel` 双向同步（`file://` 下部分浏览器受限，退化为手动翻页） |
| 当前/下一页预览 | ✅ | 按设计分辨率 `transform:scale()`，像素级对齐 |
| 讲稿显示 | ✅ | `<div class="notes">`，SCRIPT 卡 |
| 分段计时 | ✅ | 演讲窗自带 timer |
| 激光笔 | ❌ | 本库不提供。要真激光笔只能靠系统级指针工具，与 deck 无关 |
| 排练记录（回看每页停留时长） | ❌ | 本库不提供，也不打算做——它需要持久化，与「单文件离线可开」冲突 |

**口径**：默认走本库 B 出口。用户明确要激光笔或排练记录时，**直说本库没有**，不要含糊承诺，也不要为此引入外部引擎——那会把一份单文件 deck 变成有外部依赖的工程。

## 讲稿落三处的映射

| 出口 | 讲稿放哪 | 怎么验 |
|---|---|---|
| A 影像 | `notes.json`（`{"03-slide-traction.png": "讲稿…"}`），merge 时写进 pptx 备注页 | pptx 里开备注视图看 |
| B 网页 | `<div class="notes">` 内 | 按 `S`，SCRIPT 卡应出现这页讲稿 |
| C 可编辑 | ppt-master 的备注页 | 打开备注栏 |

讲稿长度与内容在 `pages/NN.md` 的 `notes` 字段里维护——三个出口都从这里取，别各写一份。
