# 提示词配方（五型：判型 → 出提示词）

> 本库不生成文字，但「写」这件事有型。型选错，九条判据只会把错的东西判得更整齐。
> 判据正本在 `prose-gate.md`；本卷管**判哪一型、那一型该怎么写**。提示词正本在
> `scripts/pick-recipe.py` 的 `RECIPES`（⛔ 这里不抄第二份，改提示词只改脚本）。

## 五型一览

| key | 型 | 什么时候用 | 骨架（四段） |
|---|---|---|---|
| `briefing` | 汇报 | 对上：周报、进度、评审 | 结论先行 → 主张＋证据＋一个数 → 下一步只做一件事 |
| `proposal` | 提案 | 要资源：立项、预算、报价、合作 | 问题与代价 → 做法（≤3 步，每步一个可验产物）→ 证据 → 要什么（钱/人/时间） |
| `teaching` | 讲解 | 培训、科普、机制说明 | 槽位（由哪几个角色构成）→ 前置 → 典型性阶梯（典型/边缘/反例）→ 边界 |
| `retro` | 复盘 | 收尾、事故、发布后 | 事实（时间线）→ 根因写到可改那层 → 改什么（谁/何时验）→ 这次不改的 |
| `launch` | 发布 | 对外：上线、版本、产品页 | 一句主张（给谁、省什么）→ 三条可核证据 → 一条限制 → 一个动作 |

```bash
python3 scripts/pick-recipe.py --list
python3 scripts/pick-recipe.py --detect 草稿.md      # 或直接喂 spec / deck.json
python3 scripts/pick-recipe.py --show teaching       # 出这一型提示词，可直接贴进对话
python3 scripts/check-prose.py deck.json --suggest    # 闸跑完顺手判型
```

## 判型规则

只看内容，不看文件名：**触发词**＋**结构信号**（有「下一步/预算」像提案，有「根因/教训」像复盘，
「为什么/由…组成」像讲解，「上线/发布」像发布，「进展/完成」像汇报）。三语都认，**中文优先**：

| 语言 | 计分 | 匹配方式 |
|---|---|---|
| 中文 | 命中 ×2（同一词最多计 3 次） | 子串计数（中文没有词边界） |
| 英/日 | 命中 ×1 | 词边界匹配（`report` 不命中 `reporter`，允许复数与词尾变化） |

同一份里中英混排，作者用哪种语言写的就按哪种走——中文证据压过外文证据（实测
`mixed-zh-first.md`：中文「汇报/进展/完成」7 分 vs 英文 budget/proposal 2 分）。
头名与次名差 ≤2 就算**两型都对**，输出会明说，别硬挑一型。

判型不判内容好坏——好坏归九条判据。两件事分开跑，是因为「这是汇报体写得像提案」这种错，
任何单条判据都抓不到。

## 提示词里编进了什么

每条配方都是固定五段，不是自由发挥：

1. **角色与输出形态**：写明输出是 deck spec（`slides[]`，页型从本库八个里选），不是散文。
2. **硬要求**：能用数检查的（≤26 字、一条一个句读、数字带 `source`、结尾只给一件事）——
   与九条判据同源，写的时候就把闸满足了，不靠写完再改。
3. **禁词**：与 `check-prose.py` 的 `BAN` 同表（赋能/闭环/抓手/一站式/全链路…）。
4. **收尾四问**（借文案语域的四判据，改成问句）：换个主题还成立吗？谁在说、为什么说？
   删掉这句会掉信息吗？这句有来处吗？——四问是给写的人自查用的，⛔ 不替代 `check-prose.py`。
5. **型的骨架**：来自三条写法路径的落形——讲解型的「槽位 / 前置 / 典型性 / 边界」就是框架语义＋
   脚本＋原型三件，汇报与提案则是「一页一主张」加代价与要什么。

## 两型都对时怎么办

按本库老规矩：**分段写，不混段**。例如「这次事故的复盘 + 下一步预算申请」，前四页按 `retro`，
后两页按 `proposal`，页序上明说换型（kicker 里写清「复盘」「申请」），别让一页里既归因又要钱。

外文稿的提示词仍是中文（配 `--show <key>` 时末尾附一条折算规则：26 字 ≈ 54 字符、禁词按同义替换），
⛔ 不另出一套英文提示词——两套文案会漂。

五型都覆盖不了的内容（纯叙事、纯诗、纯数据表），就不判型：`--detect` 会给 0 分并提示
「补一句这是给谁看的、要他做什么」——那通常是内容还没成形，先回 Step 1 想清楚，别急着上版式。
