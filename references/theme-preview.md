## 何时用

- 新 fork 一个主题后，要一张能一眼看清配色/材质/按钮/版式的总览页；
- 用户问「这个主题长什么样」「和实景照片像不像」时的视觉依据；
- 主题改完（材质、字体、按钮高光、色板）后的验收件。

⛔ 这不是 deck 本身：预览板是 1080×720 的静态风格板，不带翻页/演讲者模式。要真 deck 走 `references/path-b-html.md` + `scripts/build-deck.py`。

## 入口与产物

```bash
python3 scripts/gen-theme-preview.py <主题名> <中文名> <英文名> [--dark|--aero]
# 世纪广场：不加标志
# 世纪大道：--dark
# 广兰路：  --aero
```

- 脚本：`scripts/gen-theme-preview.py`（自定位，不依赖工作区）
- 模板：`scripts/preview-template.html`（模板正文从 marker 之后取）
- 产物：`examples/previews/<主题名>-theme-preview.html`（省略输出路径时自动建目录）

## 三种 flavor 与判据

| flavor | 主题 | 关键差异 |
|---|---|---|
| 默认（无标志） | 世纪广场 | 内化智造黑 + 世纪亮黄色板；套 `LIGHT_STEEL_OVERRIDE` + `LIGHT_MARBLE_OVERRIDE` + `PILL_ALIGN_OVERRIDE`；Line 2 → Line 9 标签更正（色值不变） |
| `--dark` | 世纪大道 | 暖光灯箱夜景覆盖；黑金大理石 + 黄字；同上按钮居中；Line 2 → Line 9 |
| `--aero` | 广兰路 | 提 Google Fonts `@import` 到样式表首位；补 token 别名；**跳过**按钮居中与 Line 9 替换；色板换成广兰路四色 |

⛔ `--dark` 与 `--aero` 互斥，脚本会拒绝混用。

## 生成链路（脚本内部，改动前先读懂）

1. `assets/fonts.css` 去掉远程 `@import` → `inline_fonts()` 转 data URI；
2. 读 `assets/themes/<主题名>.css`；`--aero` 时把主题自带的 Google Fonts `@import` 单独摘出；
3. 模板从 `/* ===== 预览页专用版式（不属于主题） ===== */` 之后截断（marker 之前的世纪广场主题 CSS **不进**产物）；
4. 拼接 `<head><style>`：imports（若有）→ 内化字体 → 主题 CSS → 模板 tail；
5. 覆盖段必须插在 `</style>` **之前**——追加到文件末尾会落在 `</body>` 后，完全无效（踩过）；
6. 裸 `h2/h3/h4/h1` 补 `font-family:var(--font-display)`，否则标题落回宋体（踩过）；
7. 名称替换：`Century Sq`（大写 `CENTURY SQ`）→ 英文名、`世纪广场` → 中文名；非 `--aero` 才做 Line 9 替换；
8. 写后回读文件大小，打印 `OK <路径> (<KB> KB) | 主题 | 中文 英文 | dark=… aero=…`。

## 接入新主题的 checklist

先把新主题归到已有 flavor；确实都不匹配再新增 flavor。逐项确认：

- [ ] **token 依赖**：模板用 `--primary` / `--line-4` / `--accent-ink` / `--font-mono` 等。新主题缺哪个就补别名（`--primary:var(--accent)` 之类），否则结构件变透明。
- [ ] **`@import` 位置**：CSS 规范要求 `@import` 排在除 `@charset`/`@layer` 外所有规则前。主题自带远程字体时，必须提到 `<style>` 首位，内联到中段浏览器会忽略（踩过）。
- [ ] **按钮 padding**：世纪主题用 `PILL_ALIGN_OVERRIDE` 修正旧 CJK 补偿；若主题自己有 `::before` 高光胶囊（如广兰路 Frutiger 高光），⛔ 别套——胶囊按按钮高度定位，套上去就变形。
- [ ] **线路标签**：Line 2 是广兰路真实线路，⛔ 不做 Line 9 替换；世纪主题的 Line 9 是资料更正（色值 `#0090CD` 不变）。
- [ ] **色板硬编码**：模板色板写死了世纪四色与 LINE 标签，新主题必须整段替换成自己的色值与标签名，否则标题台与色板自相矛盾（踩过）。
- [ ] **概念层（不只是色值）**：模板的材质圆/几何/导视文案都是**世纪广场的概念**——清水混凝土、抛光大理石、拉丝钢、柯布西耶模度、磨砂浮层「不做厚倒角强折射」。若新主题的语言相反（如广兰路 Frutiger Aero＝玻璃亮带＋气泡＋白瓷＋厚折射），必须连概念一起换：材质圆词与纹理、几何标题与圆点/方网格、卡片正文描述、导航栏目（广场/公园/植被 → 园区/厂区/绿化）、页眉 meta 的路径与材质措辞、组件卡底纹（混凝土点阵 → 白瓷托盘）。⛔ 只换色值不换概念，会出现「广兰路标题配大理石文案」这种矛盾（2026-11-20 踩过并修）。
- [ ] **`cp-*` 组件类**：`.cp-btn-2` / `.cp-alert` / `.cp-anchor` 定义在模板 marker 之前，不随 tail 进产物；主题若也没定义，需在 override 里补兜底，否则组件卡显示裸文字（踩过）。
- [ ] **背景硬编码**：模板 `body` / `.board` 背景、草地带是世纪灰蓝；新主题要覆盖成自己的底色。
- [ ] **边角三档**：新主题必须定义 `--radius-sm` / `--radius` / `--radius-lg`（模板按这三档画样片，缺哪档样片就读空值）。圆角语汇要与主题一致——广兰路 20px 的玻璃圆弧和虬江 2px 的纸面直角是两种瓦作，⛔ 沿用上一版数值不查。

## 分层：主题 CSS 只放「主题」，预览板样式放模板（2026-11-20 定）

主题文件曾经同时承担两个职责：主题本体（token + 通用组件）和预览板样式表（材质样片、
锚点标记、进度条）。后者只服务预览板，17 族版式与 5 套整册一个都不使用，属于错位。

**现在的分工：**

| 层 | 住哪 | 放什么 |
|---|---|---|
| 引擎 | `assets/base.css` | 版式骨架、组件基准（含 `.slide` 的 `font-size`/`line-height`） |
| 主题 | `assets/themes/<名>.css` | token、通用组件外观（`.card`/`.pill`/`.glass`）、跨主题共用类（`cp-*`） |
| 预览板 | `scripts/preview-template.html` | 主题专属材质与标记（`fb-*`/`qj-*`），带 `[data-theme="X"]` 作用域 |

**判据**：主题专属类（`fb-*`/`qj-*`）⛔ 不许出现在 `assets/themes/` 里；它们必须在模板里带
`[data-theme="<主题>"]` 前缀。`gen-theme-preview.py` 把 `data-theme` 写到 `<html>` 上，
作用域才命中。`check-preview-sync.py` 的 `check_materials` 会查这条，造错验证过会红。

**为什么不是把所有组件都挪走**：`.card`/`.pill` 是主题该管的外观（纸片还是玻璃），
`cp-*` 是跨主题共用的展示组件，它们留在主题 CSS 是对的。只有「一个主题独有、且只有预览板用」
的类才该挪。

## 验收（判据是产物本身，不是退出码）

1. **headless 截图目视**：`--headless=new --no-sandbox`（本环境 Chrome 沙箱起不来，必须带 `--no-sandbox`）。检查色板一致性、按钮高光、标题可读、无错位。
2. **一致性闸（必跑，判据级）**：`python3 scripts/check-preview-sync.py`。查**八类**静默漂移：① 色板 hex 与 `:root` 不符 ② 材质样片退回通用 `.d-*` ③ 预览页用了主题没定义的 `.cp-*` ④ 导览面板残留上游语汇 ⑤ `.g-modal` 压住卡片正文 ⑥ **模板源 `--token:#hex` 与主题真值不符** ⑦ **边角样片写死半径或缺失**（见下节「边角」）⑧ **模度阶梯读死引用**——四档 `background` 里的 `var()` 既没定义又没兜底，浏览器整条丢弃、条子静默变透明（2026-11-24 排障：虬江三条全空，闸门曾全绿；`check_modscale` 守这条）。任一条红就不许交付。⛔ 别用 `grep -c` 手工数——2026-11-20 那轮四处错都是 grep 数不出来的。

   第 ⑥ 类是 2026-11-20 第二轮补的：前五类只查**产物**，而 `scripts/preview-template.html` 是生成器的唯一输入，它写错时产物会被 `sync_palette` 救回来，闸门照样全绿。判据只对账「承载品牌色的 token」，材质固有色（大理石/草坪/玻璃渐变端色）不查——那些不跟主题走。
3. **回归闸**：`python3 scripts/check_doc_claims.py`（含 html 本地引用扫描）与 `python3 scripts/selftest.py` 都必须过（`selftest.py` 已内含第 2 条）。
4. **改前备份**：主题 CSS / 脚本 / 模板 / SKILL.md 均先留同目录 `.bak-<时间戳>` 基线。

## 边角（2026-11-24 补）

预览板此前只展示配色、材质、模度、组件，**边角从未成判据**：主题可以把 `--radius` 从 20px 压到 2px，
旧检查项一条都不会红，样本页上也看不出差别。补这一节，把边角拉成与配色同级的一档。

**样片区**：组件格（Component）里 `data-block="corners"` 的三档样片，同一形状分别用
`--radius-sm` / `--radius` / `--radius-lg`，下方标 token 名（不标 px）。位置与实现在
`scripts/preview-template.html`，判据在 `check-preview-sync.py` 的 `check_corners`。

**判据（源严产物宽）**：

- 模板源（红）：必须有该样片区；区内 `border-radius` 必须引 `var(--radius*)`，
  ⛔ 写死 px／`999px`／%；三档标签必须齐。
- 主题侧（红）：每个主题 CSS 必须真的定义 `--radius`，否则样片读空值。
- 产物侧（黄）：既有预览页缺该样片区只 WARN「待重生成补齐」，不判红——
  九个既有产物要先跑一遍生成器才带得上，判红会挡住与边角无关的改动。
  重生成：`python3 scripts/gen-theme-preview.py <主题名> <中文名> <英文名>`（`--dark`／`--aero` 按主题定）。

**四类差异**：新瓦作接入时，同一梁架样本页要能同时看出**卡片、按钮、字体、边角**四类的不同。
前两类与字体现有检查项已覆盖，边角是这一节补的第四类——只换色不算换瓦作。

**外部对照（软链，不搬）**：同一骨架多主题横向对照可看 Astryx 官方沙盒
`https://astryx.atmeta.com/sandbox/pages/example-cards/`（Meta，MIT），它按卡片/按钮/字体/边角四项
并排展示七套主题。⛔ 只当读法对照，不抄它的色值、字体与 token；本库瓦作一律自写。

## 审美判据（2026-11-20 三主题返工后补）

预览板不是色卡墙。三张板同时出问题，根因是模板把「配色」当成「四块等权色块」来展示，
而主题自己写的铁则是「单视图最多主色 + 一个次色，三色只做小面积标记」。逐项判据：

- [ ] **色板要画用色比例，不是四块等权色卡**：四块满饱和色并排会互相抢，读作油漆色卡。
      用一条比例条（主色约 55-60%，次色各 13-15%）+ 角色图例（主色/次色各自的用途），
      把主题的用色纪律直接画出来。
- [ ] **色板色值必须等于主题 `:root` 的真实值**：模板硬编码的是世纪广场亮色值，
      暗色版（世纪大道）若不替换，会出现「色板写 #F9D328、按钮却是 #F5B942」的自相矛盾。
      中性色阶那排小方块同理，暗底上留亮色灰会跳成一片浅块。
- [ ] **材质圆要能分辨（含两条 2026-11-20 虬江实测的硬伤）**：
      ⛔ **不透明底纹会吃掉 token**。砖纹/石纹这类 SVG 里若有一整块不透明 `fill`，它会把
      `background-color` 完全盖住——两档青砖（`--brick-wall` / `--brick-wall-hi`）于是渲成
      同一个颜色，ΔL*=0.0，token 成了装饰。判据：底纹 SVG 的底色必须 `fill='none'`，
      砖色一律由 `background-color` 给。实测：改前八枚样片里两枚完全同色，改后 ΔL*=9.6。
      ⛔ **环境色不占材质位**。「纸白天光」这类整页环境渐变不是材质，放进材质圆只会多一枚
      近白块（与方格稿纸 ΔL*=2.0）。材质位只放能用手摸到的东西：砖、石、水、纸、漆。
      判据：八枚样片按 L* 排序后，相邻对 ΔL* 应 ≥10；不足的要么压深、要么换掉、要么承认
      它俩是同一材质的两档（那就只留一枚）。
      混凝土要有气孔点阵、大理石要有
      够粗够深的脉纹（82px 圆里 400px 平铺的细纹看不见）、拉丝钢要有高对比丝纹、
      磨砂要比亮面明显更灰更哑。统一镜面高光只占左上一条，不能把整枚洗白。
- [ ] **几何区要有秩序**：四条无标注的随机灰条、或十二枚随机彩椭圆，都是噪声不是设计。
      模度用 1 : 1.618 递减并标数值；网格用中性底 + 选中格主色实心 + 关联格次色描边。
- [ ] **按钮层级**：次按钮不能是实心满饱和（会与主按钮抢层级）。次色只做描边与文字。
      导航条同理：只有当前项实心，其余描边。
- [ ] **语义色不能错位**：绿色是成功态，不能拿来当「分类标签」。
- [ ] **概念层要跟着主题走**：底部草地带是世纪广场的概念，广兰路（Frutiger Aero）应换成
      玻璃水线；材质圆词、几何标题、导航栏目、页眉材质说明都要同步。
- [ ] **页眉不写 fork**（2026-11-20 定）：主题 CSS 与预览页一律不出现 `fork` 字样——
      页眉 mono 行只写「来雪亭Lesciotia / B 出口主题」，meta 行只写
      `<code>assets/themes/<主题>.css</code>` + 材质词 + 日期，不挂「fork 自 xxx.css」，
      也不挂「· fork / · 暗色姐妹版 / · 自建实体」这类分类后缀。
      血缘要记就记在主题 CSS 头部注释里，用「骨架承 xxx.css」的写法，不用 fork 这个词。
      理由：预览页是给人看主题长什么样的，不是给维护者看继承树的；
      页眉写 fork 等于把内部工程史摆到成品页上。

## 已知坑速查

- **产物对、模板源错**（2026-11-20 第二轮）。`preview-template.html` 的 `--primary` 写 `#f9d328`、`--line-6` 写 `#d62768`，主题早已是 `#dab406` / `#721538`。产物靠 `sync_palette` 覆盖所以全对，闸门只查产物所以全绿——**修下游修三次，源头一次没动**。判据：模板里每个 `--token:#hex` 必须等于某个主题的真值；`check-preview-sync.py` 第 ⑥ 类守。

**生成器硬编码色板 = 必然漂移（2026-11-20 四主题同时中招）**。`gen-theme-preview.py` 早期用逐条 `('旧hex', '新hex')` 替换表，等于把主题真值抄了第二份；11-20 配色体检改 `:root` 后，12 个色值里 8 个对不上。现已改成 `read_tokens()` 从 CSS 读 + `sync_palette()` 按位置填，⛔ 别再往生成器里加 hex 字面量。同类结构性问题还有三处，一并记下：

- **主题定义了自己的材质类，预览页却用通用类**。友谊大厦有 10 个 `.fb-*`（水刷石/水磨石/鎏金/薄荷/红玻璃/白桦/顶光…），模板的材质圆却写死 `.d-*`（世纪广场的混凝土/大理石/钢）。后果不是「不好看」，是「鎏金塔身显示拉丝不锈钢」——材质语义整个错位。改法：材质圆的类名与名称一起换。
- **组件类只活在生成器里**。广兰路主题 CSS 里 0 个 `.cp-*`，预览页靠 `AERO_OVERRIDE` 内联兜底，兜底还写死旧色 `#e0632f`；且 `.cp-steel`/`.cp-tile` 连兜底都没有，导航条与转角砖直接透明。改法：组件类收进主题 CSS 本体，颜色走 token。
- **导览面板留着上游语汇**。模板的第三屏是世纪广场的公园导览（广场/餐饮/公园/植被/休憩），fork 到别的主题后没人换，于是地铁站台写着「植被与休憩」、卡片标题还是 `Century Sq`。改法：每个主题在生成器里给一份自己的 `*_guide` 替换表，`check-preview-sync.py` 的 `GUIDE_LEXICON` 守。
- **`.g-modal` 压卡**。模板定位 `top:170`，卡片自面板内 186 起，正好压住中间那张卡的正文；友谊大厦的覆盖段改成 `top:312` 仍在卡片行内（186–438），压住「提示信息」。改法：挪到 `top:430` 骑在卡片底边上，只压 8px 底边不压字。
