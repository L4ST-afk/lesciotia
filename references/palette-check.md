# 配色体检（`scripts/check-theme-colors.py`）

> 归属：`theme-preview.md` 的配色判据分卷。做主题预览板、改 `:root`、或换主色时读本卷。
> 本卷只管「色板算不算过」，不管版式与材质——那些在 `theme-preview.md`。

审美判据里的「主色 55-60%、次色 13-15%」是画出来看比例的，靠眼睛判；这里补的是**能算的三条**，
读 `:root` 的 hex token 直接算，不看截图、不联网：

| 判据 | 阈值 | 为什么是它 | 怎么修 |
|---|---|---|---|
| 主色压底 | ≥3:1 | 色块/描边与底的分界（WCAG 1.4.11 非文本对比）；低于它就糊在底上 | 加 1px 描边或 8% 深色投影，⛔ 不靠提高饱和度救 |
| 两强调色 ΔL* | ≥10 | 转灰、黑白打印、色弱场景下，ΔL*<10 的两色并成一个色阶 | 拉开明度，或给其中之一加独立编码（形状/位置/图标） |
| 两强调色 ΔH | 不落 15–40° | 落在这一带既不像同族也不像对比，读作「配色没调完」 | 推到 ≥60°（明确对比）或 ≤10°（同族深浅），比调明度有效；功能色救不了时登记换轴（见下） |
| 主色与底 ΔL* | ≥12 | 主色大面积铺底时才会丢层级 | 只在铺底版式算问题；小面积标记可忽略，但要在 css 注释里写明 |

⛔ 这三条判的是**成品色板**，不是色阶生成；`浮龟Vudgio` 那边的色阶生成判据（相邻级差、色相累计旋转）
是另一个作用域，别混用（原因见 SKILL.md「配色体检闸」那段，以及浮龟库里 token 判据卷的「色相旋转预算」）。

**但暧昧带有一条降级路径**（2026-11-20 补）：状态色（信息蓝／成功绿／警示红橙）的语义是抢来的，
警示色与暖主色天生只差 20–40°，这一带**靠色相解决不了**——实测绛红 `#b01e3c`（351.5°）配琥珀 35° 是 43.5°，
把琥珀压深到 `#b45309`（26°、5.06:1 刚好可读）又落回 38.3°；白底上「≥4.5:1 可读」与「离绛红 ≥45°」不可兼得。
所以带状态色的主题改在 css 注释里登记一行换轴：

```css
/* amb-ok: accent-2/accent-3 | 面积 12% vs 2% + 图标冗余 + 永不同框 */
```

- 依据须 ≥20 字，且盖住**面积／形状／位置**三轴中至少两轴；只写「面积大」不算（报 AMBJ，仍按不通过算）。
- 登记后这对降级为 ✅ 放行，并在报告里单列「换轴放行」一节 —— ⛔ 不静默消失。
- 登记了却没对上任何暧昧对 ⇒ 报「失效豁免」（ℹ️），改名后要顺手删掉，免得旧豁免变成永久免死金牌。

**主色压底那条也有降级路径**（2026-11-23 补）：三律给的解法是「加 1px 描边」而不是换主色，
可闸只读 `:root` 的 hex，看不见 `box-shadow: inset 0 0 0 1px var(--accent-edge)`，于是永远只能报 ⚠️。
做法是在主题 css 注释里登记一行，闸据此把 BLK 降为 BLKOK，并**把描边实际对比度算出来**一并报：

```css
/* blk-ok: primary | 五处主色实心块（.gg .cell.c7 / .ring .hub …）统一带 1px --accent-edge 描边 */
```

- 依据须 ≥20 字且写明描边／edge；依据不合格报 BLKJ，仍按不通过算。
- 闸按 `--accent-edge` 的配方（`text-1` 30% 压在 accent 上）合成一条线色，量它对主色的对比度：
  ≥1.2 视为立住（1px 线不该要求 3:1），不到就报 BLKJ 并给「加粗到 2px / alpha 提到 45%」的修法。
- 放行仍进报告「放行」一节，⛔ 不静默消失（`century-sq` 的 1.79:1 就是这样从 ⚠️ 变成 ✅ 且留痕的）。

体检只判「行不行」，判不出「该怎么改」——`scripts/pick-brand-colors.py` 补的就是另一半：给定已定的色相，
按 `--gap`（默认 10 级）把明度等距拉开、只改明度不改色相，吐出新 hex 与逐对 ΔL*。手调 ΔL* 等于闭眼摸，
紫与珊瑚只差 0.7 级那次就是这么来的。顺序固定：**先取色 → 写进 `:root` → 再体检**，⛔ 先写再慢慢试。

## 填充底上的字：静态查 token 查不出真问题（2026-11-20 定）

体检脚本按 token 判，它不知道某块色**到底有没有字**。万航渡那次（当时名吉祥寺）是活教材：
`.pill-accent` 用 `--sky-lo` 天青做底配纸白字，实测 **2.99:1**，体检却报 `clean`——
因为闸门只查 `--accent-ink` 压主色，没查「次色做底 + 白字」。

脚本里补了一条 `FILL`（ℹ️ 提示级，不计 warn）：凡品牌色 token 比字色暗、且纸白字 <4.5，
就列出来当**线索**。⛔ 它不能当结论——`--line-6` 深陶在模板里只做 `.cp-alert` 的 12px 纯色条，
没有字，报出来是假阳性。番禺路的 `--line-4` 赭黄同理（只做胶囊底，字是墨色）。

**真判据是浏览器实测**，量每个带文字元素的实际前后景：

```js
// 有效底色：向上找到第一个 alpha>0.85 的祖先背景
// 阈值按 WCAG：fs>=24px 或 (粗体且 fs>=18.66px) 用 3:1，其余 4.5:1
```

万航渡（当时名吉祥寺）实测结果：**0 处违规、0 处中文违规**。番禺路/虬江等 7 个主题同样应以此口径复核。

顺序：**先跑静态体检拿线索 → 再用浏览器实测确认**。⛔ 别拿静态 `FILL` 当交付阻断项，
也⛔ 别因为静态报 clean 就以为没问题。

### 组件层：可以静态判死的一类（2026-11-25 补）

token 层查不出「组件把错字色放到对底上」，因为色对本身合法。这类不必等浏览器：
只要 CSS 块的 `background` **恰好**是 `var(--accent)` / `--accent-2` / `--accent-3` / `--primary`，
底色是确定的，字色也是确定的，对比度就能离线算死。1.2.70 的比例条就是这么翻的车——
标签用 `--text-1` 压在 `--accent` 实色段上，短条还横跨实色与浅轨道两侧。

`check-theme-colors.py` 现按此口径逐块扫，违规记 `comp_fills` 并非零退出。判据只看四件：
1. 底必须是**纯 token 填充**；`color-mix` tint、渐变、`rgba`（叠图上的半透明蒙层）跳过——
   那些要等浏览器实测，别在这里冤判。
2. 字色只允许 `var(--accent-ink)`；`#fff`、`white`、`--text-1/2/3` 都算违规。
3. 允许子元素另设字色：父块不出字、子块各自写 `--accent-ink` 的不算（如 `.flow .node.hl`）。
4. 字号大小写不进判据：4.5:1 是默认线，大字号 3:1 的放宽**不在这条闸**里开口子——
   品牌色块上的字按 4.5 收，省得同一套组件在两种字号间来回改。

实测样本：广兰路 `.tag-chip` 白压紫玻璃 `#9c8feb` = 2.78:1、`.cp-anchor` 白压主蓝 `#1a7fb8` = 4.40:1，
改 `--accent-ink` 后为 7.18 / 4.54。全库 483 个品牌色背景块，其余合规。

## 渐变不只是两端：中段掉饱和（2026-11-23 定）

`--grad` 是两到三个 hex，浏览器按 **sRGB 直线**插值。两端色相一远，直线就会穿过色环的低饱和区，
中段发灰——蓝紫压棕那段就是这么灰的（广兰路：紫 `#9c8feb` → 棕 `#a04018`，色相差 111°，
路径彩度掉 **37%**）。肉眼看到的是「过渡脏」，参数上却一切正常。

判据进 `check-theme-colors.py`，只看两个量：

| 码 | 触发 | 读法 |
|---|---|---|
| D ⚠️ | 两端 ΔH ≥60° 且路径 **OKLCH 彩度** 相对两端最低值掉 ≥25% | 中段灰带；补 2–3 个中间色标，或改 `in oklch` |
| M ℹ️ | 沿路径 L* 反向跳 >3 级 | 明度不单调，某一段亮暗倒过来 |

为什么用 OKLCH 彩度而不是 `max-min`：深棕在 RGB 里 chroma 很大（0.53），肉眼却不艳；
用 RGB 口径算，蓝紫压棕这段反而「越走越艳」，判不出来。

修法两种，按能不能接受浏览器差异选：

1. **补中间色标（推荐）**。沿 OKLCH 色相弧取 2–3 个点，L* 与彩度同步插值，写进 `--grad`。
   广兰路补了 `#b26ebb 71%` / `#b1495a 90%`，路径彩度掉 37%→**0%**，且不依赖任何新语法。
2. **`linear-gradient(in oklch, …)`**。一行解决，但只有 Chromium 111+/Safari 16.4+ 认；
   老演示机不认会整条声明失效（色块直接没有渐变）。要用就配 `@supports` 兜底。

真源与量具：一次公开视频《什么是电影感的渐变？》 ＋ 渐变实验室 `mudong-gradient.pages.dev`
（取色、三条路线、均匀明度、黑白检查、8 色标 CSS 导出）。⛔ 别只盯彩色：把渐变转黑白再看一遍，
明度连续才叫顺，彩色好看但明度断层的渐变，投到投影仪上一样脏。
